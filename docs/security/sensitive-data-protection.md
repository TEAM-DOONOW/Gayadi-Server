# 민감정보 보호

## 현재 적용 상태

- 비밀번호는 BCrypt 단방향 해시로 저장한다.
- 현재 DB에는 주민등록번호 필드가 없다.
- Logback이 메시지와 예외 스택 트레이스를 출력하기 전에 민감정보를 마스킹한다.
- API Validation 오류에는 사용자가 입력한 `rejectedValue`를 반환하지 않는다.

## 로그 처리 기준

| 정보 | 처리 방식 | 예시 |
|---|---|---|
| 비밀번호·토큰·쿠키·API 키 | 전체 제거 | `[REDACTED]` |
| 주민등록번호 | 전체 마스킹 | `******-*******` |
| 이메일 | 부분 마스킹 | `t***@example.com` |
| 전화번호 | 부분 마스킹 | `010-****-5678` |
| 카드번호 | 부분 마스킹 | `1234-****-****-3456` |

요청·응답 본문, HTTP Header, 외부 API URL 전체를 로그로 남기지 않는다. 정규식 마스킹은 보조 수단이며 민감정보를 로그 인자로 전달하지 않는 것이 우선이다.

## DB 저장 기준

| 데이터 | 저장 방식 |
|---|---|
| 로그인 비밀번호 | BCrypt 또는 Argon2id 단방향 해시 |
| JWT·재설정 토큰 | 원문 저장 금지, 필요한 경우 해시 저장 |
| 주민등록번호 등 정부 식별자 | 가능하면 저장하지 않음 |
| 복호화가 필요한 개인정보 | AES-GCM 인증 암호화 |
| 검색·중복 검사가 필요한 암호화 값 | 별도 HMAC 검색 인덱스 사용 |

## 암호화 필드 추가 전 확인사항

1. 저장 목적과 보존·파기 기간을 확정한다.
2. 암호화 키는 코드나 DB가 아닌 KMS 또는 Secret Manager에 보관한다.
3. 키 버전과 교체 절차를 준비한다.
4. 복호화 권한과 접근 기록을 관리한다.
5. 백업과 분석 시스템에도 같은 보호 기준을 적용한다.

키 관리 방식이 정해지기 전에는 복호화 가능한 개인정보 필드를 추가하지 않는다.
