# 인증 API Rate Limit

회원가입, 로그인, Refresh Token, 초대와 비용이 큰 AI·관리 API는 Redis의 서로 다른 고정 구간 버킷으로 제한한다.

| API | 기본 한도(1분) |
|---|---:|
| 회원가입 | 5회 |
| 이메일 로그인 | 10회 |
| Google 로그인 | 10회 |
| 토큰 갱신 | 30회 |
| 초대 발급·코드 참여 | 10회 |
| AI 추천·상황 대응 | 20회 |
| 관리자 임베딩 갱신 | 2회 |

서버가 확인한 `remoteAddr`를 기준으로 하며 임의의 전달 헤더는 신뢰하지 않는다. Reverse proxy를 사용할 때는 신뢰 proxy 설정과 실제 원격 주소 정규화를 배포 계층에서 먼저 완료해야 한다.

Lua script가 증가와 최초 TTL 설정을 원자적으로 수행한다. 한도 초과는 429, Redis 장애는 인증 우회를 막기 위해 503으로 fail-closed 처리한다. 실제 Redis의 TTL과 다중 인스턴스 공유 동작은 배포 환경에서 최종 확인한다.
