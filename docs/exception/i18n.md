# 다국어 메시지

API 오류 메시지는 요청의 `Accept-Language`에 따라 한국어 또는 영어로 제공한다. 오류를 구분하는 HTTP 상태와 `code`는 언어와 관계없이 동일하다.

## 메시지 파일

메시지는 도메인별로 관리한다.

```text
src/main/resources/i18n/{domain}/
├─ messages.properties      # 한국어 기본값
└─ messages_en.properties   # 영어
```

각 파일은 DTO 검증 메시지와 비즈니스 오류 메시지를 구역으로 나눈다.

```properties
# DTO Validation
validation.invitation.code.required=초대 코드가 필요합니다.

# Business Error
error.invitation.not-found=초대를 찾을 수 없습니다.
```

## 키 작성 규칙

```text
validation.{domain}.{field}.{constraint}
error.{domain}.{reason}
```

DTO에서는 Validation 키를 지정한다.

```java
@NotBlank(message = "{validation.invitation.code.required}")
private String code;
```

ErrorCode에는 사용자 문구를 작성하지 않고 메시지 키만 지정한다.

```java
INVITATION_NOT_FOUND(
        HttpStatus.NOT_FOUND,
        "INVITATION_NOT_FOUND",
        "error.invitation.not-found"
)
```

한국어와 영어 파일에는 항상 같은 키를 추가해야 한다. `MessageBundleCompletenessTest`가 ErrorCode 메시지 누락과 치환 인자 구성을 검사한다.

## 메시지 변환 방식

- Spring `MessageSource`가 `application.yml`에 등록된 메시지 파일과 요청 언어를 기준으로 문구를 찾는다.
- DTO Validation 메시지는 Bean Validation이 어노테이션의 `{validation.*}` 키를 자동으로 변환한다.
- ErrorCode 메시지는 `ApiMessageResolver`가 `messageKey`와 메시지 인자를 `MessageSource`에 전달해 변환한다.
- 변환된 문구는 `GlobalExceptionHandler`와 Security 오류 처리기가 공통 API 오류 응답에 넣는다.

## 언어 요청

```http
Accept-Language: en
```

영어는 `messages_en.properties`를 사용한다. 헤더가 없거나 지원하지 않는 언어이면 `messages.properties`의 한국어 메시지를 사용한다. 클라이언트는 번역된 `message`가 아니라 `code`로 오류를 처리해야 한다.
