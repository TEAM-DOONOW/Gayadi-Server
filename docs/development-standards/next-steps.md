# 다음 개발 권장 순서

현재 구조 리팩토링 이후에는 여러 도메인을 동시에 확장하기보다 도메인 하나를 선택해 API 계약, DB 동작과 사용자 흐름을 완전히 검증한 뒤 다음 도메인으로 넘어가는 방식을 권장한다.

이 문서는 강제 코드 규약이 아니라 구현 완성도를 높이기 위한 권장 로드맵이다.

## 도메인 완료 방식

각 도메인은 다음 순서로 확인한다.

1. Controller의 전체 API 경로, 요청·응답과 상태 코드를 목록화한다.
2. Request Validation, 인증과 도메인 권한 조건을 검증한다.
3. Service의 정상 흐름, 경계값과 상태 전이 규칙을 테스트한다.
4. Repository SQL을 H2와 개발용 PostgreSQL에서 검증한다.
5. 존재하지 않는 데이터, 중복, 권한 부족과 동시 수정 예외를 검증한다.
6. 한국어·영어 오류 메시지와 공통 오류 응답을 확인한다.
7. Swagger 스키마와 실제 JSON 응답이 일치하는지 확인한다.
8. 단위·통합·HTTP 계약 테스트를 실행한다.
9. Android 또는 API 클라이언트에서 주요 사용자 흐름을 직접 확인한다.
10. API 명세와 관련 문서를 갱신한 뒤 해당 도메인을 완료 처리한다.

하나의 API도 정상 요청만 확인하지 않는다. 최소한 성공, Validation 실패, 인증 실패, 권한 실패, 데이터 없음과 상태 충돌을 함께 검증한다.

## 권장 도메인 순서

### 1. 인증과 사용자

1. `auth`
2. 사용자 계정·프로필 기능

회원가입, 로그인, 토큰 재발급, 인증 필터, 현재 사용자 조회·수정·탈퇴를 먼저 안정화한다. 이후 모든 도메인의 권한 테스트가 인증 기반을 사용하므로 가장 먼저 완료한다.

확인할 핵심 항목:

- 비밀번호 저장과 민감정보 로그 마스킹
- Access·Refresh Token 발급, 만료와 재발급
- 401·403 공통 오류 응답
- 탈퇴 사용자와 만료·변조 토큰 처리
- 인증이 필요한 Swagger API 표시

### 2. 사용자 관계와 초대

1. `friendship`
2. `invitation`

친구 검색·요청·수락·거절과 여행 초대 흐름을 검증한다. 사용자 간 권한과 중복 요청, 동시 상태 변경을 집중적으로 확인한다.

### 3. 여행 기본 흐름

1. `travel`
2. `coordination`
3. `survey`

여행 생성부터 참여자, 날짜 조율과 성향 설문까지 여행 전 준비 흐름을 완성한다. 여행 소유자와 참여자 권한, 상태 전이, 날짜 범위와 수정 버전 충돌을 검증한다.

### 4. 장소와 일정

1. `place`
2. `favorite`
3. `schedule`

장소 조회·찜과 일정 생성·수정·삭제·순서 변경을 검증한다. 일정 날짜가 여행 범위를 벗어나지 않는지와 동시 수정 시 순서가 보존되는지 확인한다.

### 5. 경비와 여행 화면

1. `expense`
2. `dashboard`

경비·공금·정산 계산을 먼저 고정한 뒤 여행 홈의 집계 응답을 검증한다. 금액 반올림, 합계 불변식, 삭제 데이터 제외와 참여자별 부담액을 테스트한다.

### 6. 경로와 상황 변경

1. `route`
2. `event`

경로 추천·선택과 여행 중 변경 제안 흐름을 검증한다. 외부 호출 중 DB 잠금을 유지하지 않는지, 일정 revision이 달라졌을 때 오래된 결과를 저장하지 않는지 확인한다.

### 7. 외부 데이터 연동

1. `tourapi`
2. `weather`
3. `congestion`

외부 API별 요청 파라미터, 시간 제한, 오류 매핑과 응답 파싱을 검증한다. 자동 테스트에서는 공급자를 Stub으로 대체하고, 개발 환경에서는 안전한 키로 최소 실호출 검증을 별도로 수행한다.

### 8. 추천과 AI 조합

1. `recommendation`
2. 여행 상황 대응 Agent

기반 도메인과 외부 연동이 안정화된 후 마지막으로 추천 결과의 조합을 검증한다. AI 출력은 신뢰하지 않고 스키마 검증, 허용값 제한, 시간 제한과 대체 응답을 적용한다.

### 9. 운영 지원 기능

1. `notice`
2. `legal`
3. `support`
4. Firebase 알림과 관리자 API

핵심 여행 흐름과 독립적인 운영 기능을 마무리한다. 공개 범위, 게시 상태, 개인정보 포함 여부와 관리자 권한을 확인한다.

## 도메인 완료 체크리스트

- [ ] 전체 엔드포인트의 성공 응답을 확인했다.
- [ ] Validation, 인증, 권한과 상태 충돌 응답을 확인했다.
- [ ] 실제 PostgreSQL에서 Repository 동작을 확인했다.
- [ ] Swagger와 실제 Request·Response가 일치한다.
- [ ] 한국어·영어 메시지 키가 모두 존재한다.
- [ ] 민감정보가 응답과 로그에 노출되지 않는다.
- [ ] 단위·통합·HTTP 계약 테스트가 통과한다.
- [ ] 클라이언트의 대표 사용자 흐름을 직접 확인했다.
- [ ] API·설계 문서를 현재 구현에 맞게 갱신했다.

## 권장 작업 단위

한 번의 작업 또는 PR은 가능한 한 한 도메인이나 하나의 완결된 사용자 흐름으로 제한한다. 예를 들어 `auth 전체 안정화`, `친구 요청부터 수락까지`, `여행 생성부터 참여까지`처럼 검증 가능한 단위로 나눈다.

도메인 검증 중 다른 도메인의 문제가 발견되면 임시 우회 코드를 넣기보다 이슈와 재현 테스트를 남기고 해당 도메인의 차례에서 해결한다. 단, 보안 문제나 데이터 손상 가능성이 있으면 순서와 관계없이 우선 처리한다.
